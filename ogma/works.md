# Ogma — working notes

The long form of [todo.md](todo.md): what was decided, how things are tested, what is known to be wrong, and where
each phase landed. Newest facts are added at the end of each section.

## What Ogma is

Ogma is the physics of standard machine parts and the file format that carries a frozen design: what a gearbox,
a motor, a battery, a rotor, a wing, the air and the ground *are* (data) and *do* (behaviour), independent of any
machine, simulator or design tool. `import ogma as og` → `og.mass`, `og.gears`, ….

- **Vegeta** (where machines are conceived — the larva) *fills* Ogma models: its CAD and tools (Boreas, Talos)
  compute the numbers.
- **Piccolo** (where hatched machines learn to fly) and **Chiron** *run* them.
- **Nomios / Ketos** read the files (Yax, stdlib only).
- Dependency rule: `ozaru (stdlib) ; yax (stdlib, in ogma) ← ogma (numpy) ← chiron (mujoco) ← vegeta, piccolo`.
  Piccolo never imports Vegeta; Vegeta never imports Piccolo.

Why it is stable: the physical world resists change more than code does. ISA, DC-motor lines, gear geometry and
Bekker soils do not move, so both sides can depend on Ogma like on numpy.

## Layer rules (enforced by `tests/test_no_host_imports.py`)

- `yax` is stdlib only.
- `ogma` imports numpy at module level and nothing else heavy; pandas only lazily inside display-table helpers.
- Never at module level: vegeta, piccolo, chiron, mujoco, cadquery, pandas. The test checks module-level imports
  only (function-local lazy imports are allowed — that is how the strategies will work).
- `og.__init__` loads submodules lazily from `_MODULES`; a planned but unwritten module raises
  `AttributeError("... planned")` rather than ImportError, so the README table and the code agree.

## Testing: characterisation goldens

The user's rule: *assume the current code is a source of truth*. Physics is hard to test from first principles,
so every moved or consolidated piece is pinned to what Vegeta computed:

1. Run the current Vegeta code on fixed inputs (the real design tables, fixed seeds).
2. Write its outputs to `ogma/tests/golden/<module>.json`, with a `source` naming the Vegeta commit and functions.
3. The Ogma test feeds the same inputs to Ogma and requires the same outputs (tolerances 1e-12 unless stated).

Goldens are **always generated by script from Vegeta**, never typed by hand (a hand-typed one was wrong once).
Published references (Shigley, Wong, ISA tables, datasheets) are added on top where they exist.

| Golden | Recorded from |
|---|---|
| `mass.json` | Vegeta 055e55f — `kestrel_systems.cg_inertia`, `nisus_systems.cg_inertia` on the real tables |
| `parts.json` | the O2 moved modules (gears, soil, tracks, cutting, actuators) |
| `atmosphere.json` | Vegeta 385738d — `boreas.microjet.isa`, `nisus_plus_systems.atmosphere/density_altitude`, `velutina_flight.isa_density` |
| `wind.json` | Vegeta 79cb849 — `nisus_robot.Wind(steady=(3,-1,0), sigma=1.5, tau=4, gust=…, seed=7)` |
| `batteries.json` | Vegeta e918c97 — `nisus_plus_systems` LiIonCell/LiIonPack/CELLS, `nisus_systems` Battery/BATTERIES |

## Phase log

### O0 — repo + Yax (04b6566)
- `yax/` moved from Ozaru with `git filter-repo --path yax/`; history visible (462e0c9 "Add Yax").
- Two distributions: `yax/` (stdlib, installable alone) and `ogma/` (numpy).
- Ozaru dropped Yax on its session branch (8508053). Vegeta and Piccolo vendor `vendor/ogma` as a squashed subtree
  with `scripts/update_ogma.sh` and `vendor/OGMA_REVISION`.

### O1 — foundations (64cb354)
- `og.units`: `G = 9.80665` (standard), `G_VEGETA = 9.81` (what Vegeta's machines used; kept so goldens hold until
  the constants unification).
- `og.frames`: quaternions, rotations, Euler, the aero ↔ body frame conventions.
- `og.mass`: thin shapes (Rod, Plate, Shell) as Vegeta's budgets idealise them; solid shapes (Box, Sphere,
  Cylinder, Ellipsoid) with MuJoCo's `inertiafromgeom` formulas; `Item`, `Budget`, `MassProperties` (+, shift);
  `place_for_cg` — the algebra every Vegeta table repeated for its battery.
- Vegeta: `kestrel_systems.cg_inertia` and `nisus_systems.cg_inertia` are thin adapters over `og.mass.Budget`,
  goldens identical.

### O2 — generic modules moved with history (9820e35, 934c473)
- `designs/gears.py`, `tracks.py`, `terramechanics.py` (→ `og.soil`), `cutting.py`, `actuators.py` moved with
  filter-repo, then packaged. Vegeta designs import `from ogma import actuators as act`, `from ogma import soil as tm`.
- The old Vegeta modules were removed, not shimmed.

### O3 — consolidation (3325c40, 768f6bc, 60de784, a73b4a7, 04f6595)
- `og.atmosphere` (3325c40): `isa`, `atmosphere`, `density_altitude`, `density`; reproduces all three Vegeta ISA
  copies. Vegeta's `nisus_plus_systems` and `velutina_flight.isa_density` now call it.
- `og.wind` (768f6bc): `Wind` = steady + OU turbulence (exact discretisation) + 1−cos gust, from `nisus_robot.Wind`.
  Vegeta's `nisus_robot` uses it.
- `og.batteries` (60de784): `LiIonCell`/`Cell`, `LiIonPack`/`Pack`, `CELLS`, `CHARGE_MIN_C`, `Battery`, `BATTERIES`.
- `og.rotors` (a73b4a7): `x_layout`, `allocation`, `mix` (desaturating), `lag_alpha`, `wrench` **about the COM**,
  `quadratic_drag`, `induced_velocity`. Drongo's layout/wrench/mix and `kestrel_flight.induced_velocity` use it.
- `og.propulsion` (04f6595): `PropulsionMap`, `ElectricDrive` (was `NisusPlusDrive`), `Unit`, `DriveTable`;
  `RHO0 = RHO = 1.225`. The classes were extracted verbatim (AST spans) from Vegeta so the goldens hold bit-for-bit.
  Next: Vegeta imports them (`NisusPlusDrive = ElectricDrive` under the old name), Piccolo's `races/refquad.Drive`
  could become `og.propulsion.DriveTable`.

## Known issues and deliberate number changes

- **Races COM-torque bug (fixed).** `races/sim.py` applied rotor torques about the body origin, not the COM
  (MuJoCo's `xfrc_applied` acts about the COM). Fixed in Piccolo by using `og.rotors.wrench`; the MuJoCo golden was
  re-recorded. **The user should re-tune `races/autopilot.json`** — the old gains were tuned on the wrong torques.
- **Falco `fuselage:` rows get no shape inertia.** `nisus_systems.cg_inertia` picks shapes by item-name prefix and
  Falco's fuselage rows match none, so they count as point masses. Known, not yet changed; fixing it is a reported
  golden change.
- **Constants drift.** About 60 local constants disagree: `G` 9.81 vs 9.80665, `RHO` 1.2 vs 1.225. Ogma keeps
  `G_VEGETA` for now; unifying is its own commit per golden that moves, with the reason written down.
- **Velutina's wind** is a separate model, not yet on `og.wind`.
- **Still duplicated in Vegeta:** three motor fits to a published point, two near-identical aero hooks, ~10 copies
  of the turbulent Cf formula, 7 battery-for-CG solves, 4 `quat_to_R`.

## Strategies (O5–O7): how Ogma meets engines

Decision: Ogma gains *strategies* for MuJoCo (O5), then CAD (O6), then Gazebo (O7) — like an ORM's dialects.

- A strategy only **translates** Ogma parts into the engine's terms; it never holds physics. The physics stays in
  the laws, so the three engines agree by construction.
- The engine is imported lazily inside the strategy and installed as an optional extra
  (`ogma[mujoco]`, `ogma[cad]`, `ogma[gazebo]`); `import ogma` stays numpy-only.
- **O5 MuJoCo:** MJCF fragments (inertials, geoms, actuators from `og.motors`). Chiron keeps its contact/servo
  policy; Chiron's test pins Ogma shape inertia to `inertiafromgeom` per shape (1e-9).
- **O6 CAD:** CadQuery geometry from parts; `export_yax`'s OCC mass properties move here from Vegeta's Dedalus.
- **O7 Gazebo:** SDF inertials/links/joints, `MulticopterMotorModel` constants from a propulsion map, `DiffDrive`
  from a wheel pair — replacing the hand-copied values in Piccolo's drako/iguana SDF.
