# Ogma — working notes

The long form of [todo.md](todo.md): what was decided, how things are tested, what is known to be wrong, and where
each phase landed. Newest facts are added at the end of each section.

## What Ogma is

Ogma is the physics of standard machine parts and the file format that carries a frozen design: what a gearbox,
a motor, a battery, a rotor, a wing, the air and the ground *are* (data) and *do* (behaviour), independent of any
machine, simulator or design tool. `import ogma as og` → `og.mass`, `og.gears`, ….

- **Vegeta** (where machines are conceived — the larva) *fills* Ogma models: its CAD and tools (Boreas, Talos)
  compute the numbers.
- **Piccolo** (where hatched machines learn to fly) and **Chiron** *run* them.
- **Nomios / Ketos** read the files (Yax, stdlib only).
- Dependency rule: `ozaru (stdlib) ; yax (stdlib, in ogma) ← ogma (numpy) ← chiron (mujoco) ← vegeta, piccolo`.
  Piccolo never imports Vegeta; Vegeta never imports Piccolo.

Why it is stable: the physical world resists change more than code does. ISA, DC-motor lines, gear geometry and
Bekker soils do not move, so both sides can depend on Ogma like on numpy.

## Layer rules (enforced by `tests/test_no_host_imports.py`)

- `yax` is stdlib only.
- `ogma` imports numpy at module level and nothing else heavy; pandas only lazily inside display-table helpers.
- Never at module level: vegeta, piccolo, chiron, mujoco, cadquery, pandas. The test checks module-level imports
  only (function-local lazy imports are allowed — that is how the strategies will work).
- `og.__init__` loads submodules lazily from `_MODULES`; a planned but unwritten module raises
  `AttributeError("... planned")` rather than ImportError, so the README table and the code agree.

## Testing: characterisation goldens

The user's rule: *assume the current code is a source of truth*. Physics is hard to test from first principles,
so every moved or consolidated piece is pinned to what Vegeta computed:

1. Run the current Vegeta code on fixed inputs (the real design tables, fixed seeds).
2. Write its outputs to `ogma/tests/golden/<module>.json`, with a `source` naming the Vegeta commit and functions.
3. The Ogma test feeds the same inputs to Ogma and requires the same outputs (tolerances 1e-12 unless stated).

Goldens are **always generated by script from Vegeta**, never typed by hand (a hand-typed one was wrong once).
Published references (Shigley, Wong, ISA tables, datasheets) are added on top where they exist.

## Phase log

### O0 — repo + Yax (04b6566)
- `yax/` moved from Ozaru with `git filter-repo --path yax/`; history visible (462e0c9 "Add Yax").
- Two distributions: `yax/` (stdlib, installable alone) and `ogma/` (numpy).
- Ozaru dropped Yax on its session branch (8508053). Vegeta and Piccolo vendor `vendor/ogma` as a squashed subtree
  with `scripts/update_ogma.sh` and `vendor/OGMA_REVISION`.

### O1 — foundations (64cb354)
- `og.units`: `G = 9.80665` (standard), `G_VEGETA = 9.81` (what Vegeta's machines used; kept so goldens hold until
  the constants unification).
- `og.frames`: quaternions, rotations, Euler, the aero ↔ body frame conventions.
- `og.mass`: thin shapes (Rod, Plate, Shell) as Vegeta's budgets idealise them; solid shapes (Box, Sphere,
  Cylinder, Ellipsoid) with MuJoCo's `inertiafromgeom` formulas; `Item`, `Budget`, `MassProperties` (+, shift);
  `place_for_cg` — the algebra every Vegeta table repeated for its battery.
- Vegeta: `kestrel_systems.cg_inertia` and `nisus_systems.cg_inertia` are thin adapters over `og.mass.Budget`,
  goldens identical.

### O2 — generic modules moved with history (9820e35, 934c473)
- `designs/gears.py`, `tracks.py`, `terramechanics.py` (→ `og.soil`), `cutting.py`, `actuators.py` moved with
  filter-repo, then packaged. Vegeta designs import `from ogma import actuators as act`, `from ogma import soil as tm`.
- The old Vegeta modules were removed, not shimmed.

### O3 — consolidation (3325c40, 768f6bc, 60de784, a73b4a7, 04f6595)
- `og.atmosphere` (3325c40): `isa`, `atmosphere`, `density_altitude`, `density`; reproduces all three Vegeta ISA
  copies. Vegeta's `nisus_plus_systems` and `velutina_flight.isa_density` now call it.
- `og.wind` (768f6bc): `Wind` = steady + OU turbulence (exact discretisation) + 1−cos gust, from `nisus_robot.Wind`.
  Vegeta's `nisus_robot` uses it.
- `og.batteries` (60de784): `LiIonCell`/`Cell`, `LiIonPack`/`Pack`, `CELLS`, `CHARGE_MIN_C`, `Battery`, `BATTERIES`.
- `og.rotors` (a73b4a7): `x_layout`, `allocation`, `mix` (desaturating), `lag_alpha`, `wrench` **about the COM**,
  `quadratic_drag`, `induced_velocity`. Drongo's layout/wrench/mix and `kestrel_flight.induced_velocity` use it.
- `og.propulsion` (04f6595): `PropulsionMap`, `ElectricDrive` (was `NisusPlusDrive`), `Unit`, `DriveTable`;
  `RHO0 = RHO = 1.225`. The classes were extracted verbatim (AST spans) from Vegeta so the goldens hold bit-for-bit.
  Next: Vegeta imports them (`NisusPlusDrive = ElectricDrive` under the old name), Piccolo's `races/refquad.Drive`
  could become `og.propulsion.DriveTable`.

- `og.aero`: `cf_turbulent(re, mach, re_min)` (the ten build-up copies; the Mach factor divides by exactly 1 at M = 0
  so it is bit-identical to the plain form), `cf_mixed` (Kestrel), `Airframe` (Merlin; `g` field defaults to
  `G_VEGETA`), `Polar` + `viterna_cd90` (Kestrel), `stability_coefficients(c, …, crow=0)` — Nisus and Nisus+ were
  the same model; at crow = 0 they agree bit-for-bit, so one function serves both. `air_angles` + `aero_wrench`
  are the generic core of `nisus_robot.Aero.__call__` (tested by properties: drag opposes the air velocity, lift is
  up — the hook's MuJoCo loop can't run without mujoco). `vlm` and its lattice helpers copied verbatim from
  `peregrine_flight` (no CadQuery needed); also checked against Helmbold (8 %, as Vegeta's own test).
  Not taken: the Talos/Aeromant CFD and the per-machine `aero()`/`derivatives()` builders — they *compute*
  coefficients and stay in Vegeta.

- `og.motors`: `DCMotor` (= Boreas's `Motor`, verbatim; alias `Motor`), `fit_resistance` (R = (V − rpm/Kv)/I, the
  Nisus+/Falco fits), `operating_point` (Falco's `_static_point` / the frame study's bisection with the load as a
  callable — the BEMT stays in Vegeta and is passed in), the servo law verbatim from Chiron (`torque_limit`,
  `servo_torque`, `implicit_slope`, `saturation`), `lever` and `gearbox`. Boreas keeps its own `Motor` for now: the
  tools are independent packages and Boreas is a tool, not a design (blessed imperfection). Chiron keeps its
  `servo.py` until it vendors Ogma.
- `og.__init__` now also lists the planned strategies `mujoco`, `cad`, `gazebo` (they say "planned").

- `og.mass.place_mass_for_cg(mass, moment, kg, target, bay)` and `cg_with` (added along the Vegeta refactor, V3.9):
  the battery-for-CG algebra for tables that keep their own sums (lists of dicts, DataFrames); `place_for_cg` (on a
  `Budget`) now calls it. Rule from the user: anything Vegeta's refactor finds missing in Ogma is added on the way.

- `og.wind` building blocks (added for Velutina, V3.10): `from_direction`, `linear_shear`, `power_law`,
  `ou_euler_step` (Euler–Maruyama OU with per-axis scale: Velutina varies sigma in the turbine's wake, so the
  exact-discretisation `Wind` does not fit it). Golden: `wind.json["velutina"]` (Vegeta 965fbe7).

### O5 — MuJoCo strategy
- `og.mujoco`: `geom` (MuJoCo half sizes; cylinder/capsule along z, quat for x/y), `inertial` (fullinertia from a
  `MassProperties`), `body` (a budget's inertial + visual non-colliding geoms; thin shapes and point masses count in
  the inertial only), `model`, `compile_check` (the only place `mujoco` is imported). `og.mass.Capsule` added (MuJoCo's
  formula: mass split by volume, hemispheres by parallel axes). Tests compile with MuJoCo: every solid shape's
  `body_inertia` equals Ogma's to 1e-9, a five-item rover budget's mass/COM/principal inertias equal
  `Budget.properties()`. MJCF *robots* (joints, contacts, servos) stay Chiron's.

### O6 — CAD strategy
- `og.cad`: `mass_properties` (OCC GProp, moved verbatim from `vegeta.dedalus.yax_export`; takes a Workplane, a
  Shape or a TopoDS_Shape), `mass_section` (the Yax `mass` block, was Dedalus's `_mass`), `properties` (→
  `og.mass.MassProperties` in SI), `solid` (Box, Cylinder, Sphere → CadQuery, in mm by default). Golden
  `cad.json` from Dedalus (Vegeta 15c4132); the solids agree with the budget shapes' MuJoCo formulas to 1e-6.
  Thin shapes (rod, plate, shell) and ellipsoids raise: they are budget idealisations, the design's CAD builds them.
  Tests skip without CadQuery (`pytest.importorskip`).
- `og.cad` brought level with `og.mujoco` (2026-10-21): solids for all five shapes (capsule = cylinder ∪ two spheres,
  ellipsoid = a stretched sphere via `gp_GTrsf`), thin shapes as `thin=` visual stand-ins, `assembly(budget)` (a
  CadQuery Assembly, a part per shaped item, coloured by group), `assembly_properties(budget)` (= `Budget.properties()`
  to 1e-5, solids from OpenCascade), `export` (STEP/STL). `mass_properties(precision=)`: OpenCascade's default fixed
  rule is 0.4 % off on spline surfaces (the ellipsoid); `properties()` integrates adaptively to 1e-9 by default
  (Dedalus's path keeps the default, its golden unchanged).

## Known issues and deliberate number changes

- **Races COM-torque bug (fixed).** `races/sim.py` applied rotor torques about the body origin, not the COM
  (MuJoCo's `xfrc_applied` acts about the COM). Fixed in Piccolo by using `og.rotors.wrench`; the MuJoCo golden was
  re-recorded. **The user should re-tune `races/autopilot.json`** — the old gains were tuned on the wrong torques.
- **Falco `fuselage:` rows got no shape inertia (fixed in Vegeta 2026-10-21).** `nisus_systems.cg_inertia` now matches
  `pod:` and `fuselage:` shell rows: Falco Iyy +4.4 %, Izz +1.8 %, Ixx +0.1 %.
- **Constants drift (resolved for the design models, V3.11).** `og.aero.Airframe.g` defaults to `G` = 9.80665
  (its golden still checks Merlin's 9.81 numbers with `g=G_VEGETA`); Vegeta's design models take `G`/`RHO0` from
  `og.units`. The Chiron robots and controllers keep 9.81 — Chiron's MuJoCo gravity — until they graduate.
- **Velutina's wind** is a separate model, not yet on `og.wind`.
- **Still duplicated in Vegeta:** three motor fits to a published point, two near-identical aero hooks, ~10 copies
  of the turbulent Cf formula, 7 battery-for-CG solves, 4 `quat_to_R`.

## Strategies (O5–O7): how Ogma meets engines

Decision: Ogma gains *strategies* for MuJoCo (O5), then CAD (O6), then Gazebo (O7) — like an ORM's dialects.

- A strategy only **translates** Ogma parts into the engine's terms; it never holds physics. The physics stays in
  the laws, so the three engines agree by construction.
- The engine is imported lazily inside the strategy and installed as an optional extra
  (`ogma[mujoco]`, `ogma[cad]`, `ogma[gazebo]`); `import ogma` stays numpy-only.
- **O5 MuJoCo:** MJCF fragments (inertials, geoms, actuators from `og.motors`). Chiron keeps its contact/servo
  policy; Chiron's test pins Ogma shape inertia to `inertiafromgeom` per shape (1e-9).
- **O6 CAD:** CadQuery geometry from parts; `export_yax`'s OCC mass properties move here from Vegeta's Dedalus.
- **Vegeta application (after O6, user decision 2026-10-21):** Vegeta vendors Ogma (`vendor/ogma`, squashed
  subtree via `scripts/update_ogma.sh`; already in place since O0) and is reworked to stand on it: designs take
  parts, mass budgets, propulsion and aero from `og.*`, CAD from the O6 strategy, Yax export from Ogma.
- **O7 Gazebo (deferred to Later, user decision 2026-10-21):** SDF inertials/links/joints, `MulticopterMotorModel` constants from a propulsion map, `DiffDrive`
  from a wheel pair — replacing the hand-copied values in Piccolo's drako/iguana SDF.

## 2026-10-21 — Ogma comes home, Yax becomes the converter

User decision: platforms exchange **standard files** (Piccolo URDF/SDF, Vegeta MJCF and JSBSim, CadQuery STEP, USD as
the universal file). Yax becomes the converter between them, with USD as the hub, in its own repository
(`technolog-spectrumai/yax`, history kept). Ogma, the parts library, moves into Vegeta at `ogma/` (history kept,
`import ogma as og` unchanged); the Ogma repository is retired with a pointer.

Consequences:
- Piccolo and Chiron no longer depend on Ogma (Piccolo must not import Vegeta): Chiron's servo law is its own code
  again, and the races keep a copy of `mix`, `wrench` and `quadratic_drag` in `races/rotors.py`.
- Vegeta and Piccolo vendor Yax (`vendor/yax`, `scripts/update_yax.sh`).
- Ogma's layer test now says: numpy and the standard library at import time, and never Vegeta, not even lazily
  (Vegeta's designs import Ogma, never the reverse).
- The Yax-side parts of the old rules (stdlib only) are Yax's own business now: Yax 2 depends on numpy and usd-core,
  and its engines (mujoco, cadquery, jsbsim) are optional extras.
